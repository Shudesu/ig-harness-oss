# 更新手順と移行サポート（2026-11-15 リリース）

このリリース（2026-11-15）で「統合ログイン対応」「公開返信のスレッド返信」「既読＋入力中」「配信ガードレール」などが加わりました。この章は、すでに IGハーネス（自前ホストまたは The Harness Cloud）を動かしている方向けの**更新と移行の手順**です。エンジニアでなくても進められるように書いています。

- **いちばん大事なこと**: これまで使ってきた従来方式（Instagramログイン、`IGAA…` トークン）のアカウントは、更新後も**そのまま動き続けます**。設定の書き換えは不要です。
- データベースの更新（migration 0024・0025）は**追加だけ**です。既存の列や行の値は変更せず、新しい列と表を足すだけなので、既存のアカウント情報・配信履歴が消えることはありません。

## 1. 更新で何が変わるか（ざっくり）

| 変更 | 内容 | 今の運用への影響 |
|---|---|---|
| 統合ログイン対応 | 新しいMetaアプリ（`EAA…` トークン）で接続できるようになる | 既存アカウントは変更なし。新しいアプリ/アカウントを足すときに使える |
| 公開返信がスレッド返信に | キャンペーン/コメントルールの返信が `/{comment-id}/replies`（スレッド）になる | 既存キャンペーンも自動でスレッド返信に変わる。元の「@付き新規コメント」に戻したいときは各キャンペーンで「@付き」を選択 |
| 失敗ログ | 返信・DM・Webhookの失敗がMetaエラーコード付きで記録され、画面で見られる | 影響なし（追加） |
| 既読＋入力中 | 自動DMの前に既読（mark_seen）→入力中（typing）を付ける | **既定が ON に変わりました**。OFFにしたい場合は下の「2」を参照 |
| 配信ガードレール | 送信窓（9-23時JST）・送信量・停止スイッチが画面で見られる | 停止スイッチは既定 OFF（送信可）なので運用は変わりません |

## 2. 更新前にチェックすること

1. **動作中のアカウント数とユーザー名をメモ**する（管理画面 → 設定 → Instagram アカウントの一覧をスクショ）。更新後に見比べます。
2. **データベースのバックアップ**（Cloudflareダッシュボード → Storage & Databases → D1 → 該当DB → Export → Download）を取ってダウンロードする。
3. 更新コマンド実行時、migration が `0024` と `0025` まで適用されることを確認する（`0025_ig_account_connection_type.sql` は既存アカウントに `connection_type`（既定 `instagram_login`）と `page_id` の列を追加するだけです）。

## 3. 更新手順（セルフホスト）

リポジトリの最新版を取って、次の順で実行します。

1. 依存の再取得 → `pnpm install`
2. migration の適用 → `pnpm db:migrate`（対象が本番D1）
3. Worker と管理画面の再デプロイ → 従来のデプロイ手順（`pnpm deploy:worker` 等）と同じ

Cloud（The Harness Cloud）の場合は当方で更新を適用するので、操作は不要です。適用後に「アカウントが壊れていないか確認」（下の「5」）だけご自身で確認してください。

## 4. 既読＋入力中が不要な場合（既定 ON を OFF に）

このリリースから、自動DMに「既読＋入力中」が付くようになりました（**既定 ON**）。

1. ダッシュボードの「配信ガードレール」カードを開きます。
2. 「既読＋入力中を自動DMに付ける」のスイッチを OFF にします。
3. これで従来と同じ「既読なし・入力中表示なし」のDMに戻ります。設定は保存され、ON/OFFはいつでも切り替えられます。

## 5. 更新後に確認すること（5分）

1. 管理画面 → 設定 → Instagram アカウント: **アカウント一覧が更新前と同じ**（消えていない・増えていない）か。バッジは従来方式のアカウントに「Instagramログイン」と出ます。
2. アカウントを1つ選んで「接続チェック」を押す: プロフィール/Webhook購読/DM権限/コメント権限がすべてOKなら正常。
3. テスターの自分アカウントからDMを1通送り、チャットに届くこと、返信が来ることを確認（**この確認は自分のアカウント間で**。お客さまのアカウントには決して送らない）。
4. 対象投稿に自分のアカウントでキーワードをコメントし、スレッド返信とDMが返ることを確認。

## 6. 統合ログインへ移す場合（任意）

従来方式のままで問題ありません。**移すのは「2026-10以降に作った新しいMetaアプリを使いたい」場合だけ**です。

1. [章9](./09-unified-login.md) の手順1〜5で新しいMetaアプリを作り、トークン（`EAA…`）と Instagram ID を用意します。
2. 管理画面 → 設定 → Instagram アカウントで、移したいアカウントの「**トークン更新**」を開き、`EAA…` トークンに貼り替えます。
3. 保存すると、バッジが「**統合ログイン**」に変わります。IGハーネスがトークンの先頭を見て自動判定するので、方式を自分で選ぶ必要はありません。
4. 一覧の「**Webhook購読**」ボタンを押します（統合ログインでは登録だけでは購読されません）。
5. 章9の「手順8」のようにテスター間でDM受信・コメント返信を確認します。

> 注意: 統合ログインのトークンは自動延長されません。失効したら「要再接続」と表示されるので、同じ手順で貼り替えます。移行先でうまくいかないときは、トークンを従来方式の `IGAA…` に戻せば元の動きに戻ります。

## 7. うまくいかないときの戻し方

1. **軽い問題**（表示だけおかしい等）: ブラウザの再読込、再度の接続チェックで様子を見る。
2. **既読＋入力中だけを止めたい**: 「4」のスイッチで OFF。
3. **スレッド返信をやめたい**: 各キャンペーン/コメントルールで返信モード「@付き新規コメント」を選ぶ。
4. **更新前に戻したい（ロールバック）**: 直前のデプロイを差し戻せば動きます。migration は追加だけなので、古いプログラムは新しい列があっても無視して動作します（列を消す操作は不要・しないでください）。データを心配するときは「2」で取った D1 のエクスポートを戻せば更新前の状態に復元できます。
5. どうしても直らないときは、失敗ログ（管理画面の「接続状態」/配信失敗一覧）のスクショと、更新前のアカウント一覧スクショを添えてご相談ください。

## 8. よくあるエラーと対処

| エラー | 意味 | 対処 |
|---|---|---|
| `code 190` | トークンが失効・無効 | 設定 → Instagram アカウントで「トークン更新」。従来方式ならトークンを再生成して貼り替え。統合ログインなら `EAA…` を作り直して貼り替え |
| `code 100, subcode 33` | 対象の投稿・コメントなどにアクセスする権限がない／対象が存在しない | アプリ（Meta側）にそのアカウントの権限（テスター設定、`instagram_manage_comments` など）があるか確認。削除された投稿への返信で出ることが多い |
| `code 200` 系 | 権限不足（Advanced Access 未取得など） | 手順に従い権限を追加しトークンを作り直す。他人のアカウントで使うにはアプリレビューが必要 |
| `(#10) … not business or creator` | Instagramアカウントがプロアカウントでない | Instagramをビジネス/クリエイターアカウントに変更 |
| `subcode 2534022 / 2018278` | 24時間送信窓の外 | 相手からの返信を待つ（送信窓の再オープン後に送れます） |
| `code 551 / subcode 2534014` | 相手のアカウントが利用不可 | 対処なし（自然に解消を待つ） |
| 更新後にDMが1件も届かない | Webhook購読が外れている | アカウント一覧の「Webhook購読」ボタンを押す（従来方式でも再購読できます） |

## 補足（技術者向け）

- migration 0024（`reply_mode_and_failures`）/ 0025（`ig_account_connection_type`）はいずれも ADD COLUMN / CREATE TABLE のみで、既存列・既存行は不変です。
- 既存アカウントは `connection_type='instagram_login'` として登録され、APIの宛先（`graph.instagram.com`）、トークン延長、Webhook購読先（IGユーザーノード）はすべて従来どおりです。
- 統合ログイン（`facebook_login`）のアカウントは `graph.facebook.com` を使い、Webhook購読先はリンク済みFacebookページ（存在すれば）です。
